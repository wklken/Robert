# Guides

## Installation

```bash
pipx install robert-github-agent --include-deps
gh auth login
robert --version
robert init --config ~/.config/robert/config.yml
robert doctor --config ~/.config/robert/config.yml
```

Runtime state is written to `~/.local/share/robert/`. Linux and macOS are
supported directly. On Windows, run Robert inside WSL.

For development:

```bash
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -e '.[dev]'
```

## First Repository

Create the initial configuration interactively:

```bash
robert init --config ~/.config/robert/config.yml
robert doctor --config ~/.config/robert/config.yml --output json
```

Or use non-interactive setup:

```bash
robert init --non-interactive \
  --config ~/.config/robert/config.yml \
  --repo example/backend \
  --repo-path /srv/repos/backend \
  --worker codex \
  --github-account robert-bot \
  --trusted-actor maintainer
```

Preview one cycle:

```bash
robert run once --config ~/.config/robert/config.yml --dry-run --skip-external
```

## Configuration Layout

Use the versioned mapping generated by `robert init`; see the
[full configuration reference](reference.md#configuration) before editing.
`workers` defines named agents, `routes` selects workers and skills, and
`route_worker_models` overrides model/effort per route. `repos` contains local
checkouts and trusted actors. `daemon` owns polling and diagnostic retention;
Omit `workflow_engine` or use `mode: sqlite` for normal operation. Existing DBOS
deployments must follow the [offline upgrade procedure](sqlite-state-machine-upgrade.md).

`robert init` writes an initial configuration, not a migration of an existing
file. Its `--worker` value supplies the executable; it currently chooses an
adapter automatically only for `codex`, `tcodex`, and `cbc`. For Claude,
OpenCode, or custom commands, explicitly edit `workers.default.adapter` and
`command` after initialization using the examples below.

After edits, validate configuration and runtime readiness before starting:

```bash
robert config validate --config ~/.config/robert/config.yml --output json
robert doctor --config ~/.config/robert/config.yml --output json
```

## Multiple Repositories

```yaml
repos:
  - full_name: example/backend
    checkout: /srv/repos/backend
    worktrees: /srv/repos/backend/.worktrees
    default_branch: main
    trusted_actors: [maintainer]
  - full_name: example/frontend
    checkout: /srv/repos/frontend
    worktrees: /srv/repos/frontend/.worktrees
    default_branch: main
    trusted_actors: [maintainer]
```

```bash
robert config validate --config ~/.config/robert/config.yml
robert status --config ~/.config/robert/config.yml --output json
```

Each worker receives the workspace belonging to its task's repository.
The global `max_concurrency` defaults to 3; each repository may set a positive
limit no larger than that global limit. Use actual checkouts and branch names.
A repository's optional `github_account` overrides the global account for event
routing; it does not switch the authenticated `gh` session.

## Worker Adapters

```yaml
workers:
  default:
    adapter: codex
    command: codex
    model: gpt-6.1-sol
    fallback_model: gpt-5.6-sol
    effort: high
    prompt_transport: stdin
    timeout_seconds: 5400
    environment_allowlist: []
```

The global hard worker timeout defaults to 45 minutes. If the two immediately
preceding terminal attempts in one workstream both end in `failed_timeout`, the
next run uses `fallback_model`. Other failure types and successful attempts
reset the sequence. The configured effort is unchanged.
For a terminal HTTP 429 or rate-limit error, Robert automatically switches to
the configured fallback on the next attempt of the same task. This uses the
task's existing one-shot automatic recovery quota and preserves its worker,
effort, worktree and context. It also works before the worker saves any progress.
If the fallback is absent, identical to the failed model, or also rate limited,
Robert records the failure and stops automatic retries. Native review/vote
switch only the affected stage and worker and retain their prompt and snapshot.

Built-in adapters are `codex`, `tcodex`, `claude`, `tclaude`, `opencode`,
`cbc`, and `command`. The generic adapter requires a YAML command sequence:

```yaml
workers:
  custom:
    adapter: command
    command: [custom-agent, --batch]
    model: default
    effort: default
```

OpenCode model names use `provider/model` form. Robert maps the worker's
`effort` value to OpenCode's model variant:

```yaml
workers:
  openai:
    adapter: opencode
    command: opencode
    model: openai/gpt-5.4
    effort: high
```

### Claude workers as root in a restricted container

The `claude` and `tclaude` adapters append `--permission-mode bypassPermissions`.
Claude Code normally refuses that mode when its process runs as root. Check
the account running the Robert service, which may differ from your login shell.

For an already restricted container that intentionally runs Robert as root,
prefix the affected worker's command with `env IS_SANDBOX=1`:

```yaml
workers:
  claude_reviewer:
    adapter: tclaude
    command: ["env", "IS_SANDBOX=1", "tclaude"]
    model: default
    effort: default
```

Use the existing worker name, model, effort, and other settings. Prepend `env`
and `IS_SANDBOX=1` to its existing command, preserving any absolute executable
path and arguments. Keep `adapter: tclaude`; for the `claude` CLI, keep
`adapter: claude` and its executable instead. Apply this to every affected
worker, including separate review and vote workers.

Robert executes an argument list without a shell. Do not use
`command: IS_SANDBOX=1 tclaude`, which treats the assignment as an executable.
The `env` prefix sets the variable for that worker without an
`environment_allowlist` entry. There is no worker `env` or `environment` mapping
in Robert YAML. Alternatively, set `IS_SANDBOX=1` in the container or service
environment and add `IS_SANDBOX` to each affected worker's
`environment_allowlist`; the allowlist passes existing values and does not
create them. Exporting a value in a terminal does not change a running service.

`IS_SANDBOX=1` bypasses Claude's root check; it does not start `bubblewrap`,
create isolation, or reduce root privileges. Do not add it automatically on an
unrestricted host. This is an upstream workaround, so recheck it when upgrading
the model CLI.

After validation, restart Robert using the deployment's existing service
manager and verify a newly created task actually starts the Claude worker.
Existing rounds can retain their saved worker configuration. A version check,
doctor result, dry run, or mocked launch does not exercise this root check;
report live startup as unverified if it is outside the authorized deployment
scope.

## External Skills

Robert validates local skills but does not install or update them:

```yaml
skills:
  search_paths:
    - ~/.agents/skills
routes:
  new-pr:
    required_skills: []
    recommended_skills: []
```

Missing required skills block before workspace creation. Missing recommended
skills appear as diagnostics.

```bash
robert doctor --config ~/.config/robert/config.yml --output json
```

## Daemon Service

Supervisor is the recommended way to run **both** `robert daemon run` and
`robert web run` on Linux, macOS, or WSL. Keep them under the same OS user as
the authenticated `gh` session and configured workers, using the same Robert
configuration and data directory. A running web process alone does not execute
queued tasks.

### Prepare Supervisor

The installation command above uses `--include-deps` to expose `supervisord`
and `supervisorctl` from Robert's Supervisor dependency. Check the commands:

```bash
command -v robert
command -v supervisord
command -v supervisorctl
command -v gh
```

If Robert was already installed without exposing dependency applications,
locate its environment with `pipx list` and use that environment's
`bin/supervisord` and `bin/supervisorctl` by absolute path. Do not start a second
Supervisor instance for the same socket.

Create runtime directories (replace these if using a custom data directory):

```bash
mkdir -p ~/.config/robert ~/.local/share/robert/run ~/.local/share/robert/logs
```

Save the following as `~/.config/robert/supervisord.conf`. Replace `/home/alice`
and `/home/alice/.local/bin/robert` with the actual home and executable paths;
on macOS the home is typically `/Users/alice`. Quote command arguments that
contain spaces. Supervisor does not expand `~` in these settings.

```ini
[unix_http_server]
file=/home/alice/.local/share/robert/run/supervisor.sock
chmod=0700

[supervisord]
nodaemon=false
pidfile=/home/alice/.local/share/robert/run/supervisord.pid
logfile=/home/alice/.local/share/robert/logs/supervisord.log
childlogdir=/home/alice/.local/share/robert/logs

[rpcinterface:supervisor]
supervisor.rpcinterface_factory=supervisor.rpcinterface:make_main_rpcinterface

[supervisorctl]
serverurl=unix:///home/alice/.local/share/robert/run/supervisor.sock

[program:robert-daemon]
command=/home/alice/.local/bin/robert daemon run --config /home/alice/.config/robert/config.yml --wait-for-lease
autostart=true
autorestart=true
startsecs=5
stopsignal=TERM
stopwaitsecs=30
stdout_logfile=/home/alice/.local/share/robert/logs/daemon.out.log
stderr_logfile=/home/alice/.local/share/robert/logs/daemon.err.log

[program:robert-web]
command=/home/alice/.local/bin/robert web run --config /home/alice/.config/robert/config.yml --host 127.0.0.1 --port 8765
autostart=true
autorestart=true
startsecs=5
stopsignal=TERM
stdout_logfile=/home/alice/.local/share/robert/logs/web.out.log
stderr_logfile=/home/alice/.local/share/robert/logs/web.err.log
```

`--wait-for-lease` keeps a restarted daemon waiting in-process when a killed
predecessor left its lease behind, instead of exiting and putting the program
into `FATAL`. On SIGTERM the daemon terminates its active child process group
and releases its lease; `stopwaitsecs=30` leaves room for that cleanup.

This example keeps Web local and read-only. For local task controls, append
`--writable --operator YOUR_OPERATOR_NAME` to the web command. Remote binding
also needs `--allow-remote` and an authenticated reverse proxy; confirm that
exposure before enabling it.

Supervisor inherits the environment that starts it; it does not source shell
startup files for each program. Start it with a `PATH` that can find `gh`, Git,
Python, and the selected worker. Keep credentials in their existing login or
host environment, never in this file. Worker-specific extra environment names
still require `workers.<name>.environment_allowlist` in Robert configuration.
See [Supervisor configuration](https://supervisord.org/configuration.html) and
[pipx dependency applications](https://pipx.pypa.io/stable/how-to/expose-apps.html).

### Start and operate both processes

Validate configuration and doctor output first. Starting the daemon can execute
tasks and publish route-authorized GitHub actions. For agent-led installation,
obtain the confirmation required by the [agent guide](agent-install.md) first.
Stop any earlier Robert service before handing the same instance to Supervisor.

```bash
supervisord -c ~/.config/robert/supervisord.conf
supervisorctl -c ~/.config/robert/supervisord.conf status
```

Wait past `startsecs` and confirm **both** `robert-daemon` and `robert-web` are
`RUNNING`. Open `http://127.0.0.1:8765/` and check `/operations` for daemon
activity, then inspect the logs if either process exits. `RUNNING` alone does
not prove successful GitHub polling or task execution.

```bash
supervisorctl -c ~/.config/robert/supervisord.conf tail robert-daemon stderr
supervisorctl -c ~/.config/robert/supervisord.conf tail robert-web stderr
supervisorctl -c ~/.config/robert/supervisord.conf restart robert-daemon robert-web
```

After editing Supervisor configuration, apply it with `reread` and `update`;
`restart` alone does not reload it:

```bash
supervisorctl -c ~/.config/robert/supervisord.conf reread
supervisorctl -c ~/.config/robert/supervisord.conf update
```

After changing Robert's YAML, restart both programs. To stop the whole managed
instance, use:

```bash
supervisorctl -c ~/.config/robert/supervisord.conf shutdown
```

Supervisor restarts managed processes while it is running. Starting Supervisor
after a host reboot remains the responsibility of the host's service manager.

### Automatic service backend (alternative)

`robert service install` chooses its backend automatically; there is no backend
selection flag. Inspect the preview before using it:

```bash
robert service install --config ~/.config/robert/config.yml --dry-run --output json
```

| Environment | Selected backend | Managed programs |
| --- | --- | --- |
| Linux with an available user systemd bus | systemd | daemon only |
| Linux without that bus | Supervisor | daemon and web |
| macOS | launchd | daemon only |

Paths are `~/.config/systemd/user/robert.service`,
`~/.config/robert/supervisord.conf`, and
`~/Library/LaunchAgents/dev.robert.agent.plist`, respectively.
**The generated Supervisor template currently uses writable Web on
`0.0.0.0:8765` with `--allow-remote`.** Edit it to the local binding above before
starting unless remote access is intended and protected by authentication.
Installing it again overwrites the service definition.

```bash
robert service install --config ~/.config/robert/config.yml
# Inspect and adjust the generated service definition before starting.
robert service start
robert service status --output json
```

On the Linux Supervisor backend, `robert service stop` shuts down Supervisor
and both programs, but `robert service restart` restarts only `robert-daemon`.
Use `supervisorctl ... restart robert-daemon robert-web` to restart both.
For the manually managed setup above, use `supervisorctl` consistently rather
than `robert service` on hosts where it selects systemd or launchd.

## Local Web UI

Start the read-only server:

```bash
robert web run --config ~/.config/robert/config.yml
```

Enable local writes explicitly:

```bash
robert web run \
  --config ~/.config/robert/config.yml \
  --writable \
  --operator "$USER"
```

Remote binding requires `--allow-remote` and an authenticated reverse proxy.
When using a proxy domain, set the browser-facing origin explicitly:

```bash
robert web run \
  --config ~/.config/robert/config.yml \
  --host 127.0.0.1 --port 8765 \
  --writable --operator "$USER" \
  --public-origin https://robert.example.com
```

Use your actual scheme, domain and public port (if nonstandard), without a path.
The proxy must preserve the browser's `Host` and `Origin` headers. Robert does
not trust `X-Forwarded-Host` or infer permitted origins from incoming requests.
For Supervisor, add `--public-origin` to the Web command in `supervisord.conf`
and restart the Web process. This setting grants no operator or repository permissions.

Writable requests require `X-Robert-CSRF-Token`. Artifact previews read only
paths registered in SQLite.

```bash
robert openclaw install \
  --plugin-dir ~/.local/share/robert/openclaw-plugin/robert-openclaw \
```


## Migration

The legacy source defaults to `~/.agents/data/dd-github-agent`; the target is
`~/.local/share/robert/`.

```bash
robert migrate dd-github-agent \
  --source ~/.agents/data/dd-github-agent \
  --target ~/.local/share/robert \
  --dry-run

robert migrate dd-github-agent \
  --source ~/.agents/data/dd-github-agent \
  --target ~/.local/share/robert
```

Migration creates a sibling backup, converts YAML, renames the SQLite account
column, and preserves compatibility with legacy idempotency markers.
