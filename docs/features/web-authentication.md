# Web 认证与远程部署

[文档目录](../README.md) · [功能专题](README.md) · [Web 启动命令](../guides.md#local-web-ui)

Web 可使用 `--basic-auth-file` 启用单个操作员的 HTTP Basic 认证。页面、API、静态资源、
产物预览和 POST 都先检查认证，再执行现有的 Host、Origin、CSRF、只读和仓库权限校验。
`--operator` 与操作范围仍由服务器配置决定，用户名不授予新的权限。

## 初始化与启动失败

`robert web auth-init --file <path> --username <name>` 两次读取无回显密码，创建权限为
`0600` 的加盐 PBKDF2-SHA256 verifier，不覆盖已有文件。verifier 应保存在仓库外。
无法关闭回显时，任一次提示都返回 `failed_input`，不会通过标准输入回退读取密码或创建文件。
无控制终端的管道和自动化脚本不能用于初始化密码；请在可关闭回显的终端运行该命令。

只有省略 `--basic-auth-file` 才表示不启用内置认证。显式传入空字符串、缺失或无效文件、
符号链接、非私有权限或非当前服务账户拥有的文件都会阻止启动，不会监听或降级成无认证。

## 远程入口与可信代理

内置监听器提供 HTTP。远程访问必须经 HTTPS 代理或受控 SSH 隧道保护；Basic 认证不加密密码。
面向不可信客户端的部署必须在可信代理上实施以下控制：

- 将 Robert 绑定到回环地址，或用防火墙仅允许可信代理连接后端。客户端不能绕过代理直接访问监听器。
- 在转发前执行全局和每来源请求速率限制，以及并发连接、突发量、排队长度和请求超时限制。
  限制必须覆盖页面、静态资源、API 和失败认证；仅按用户名限速不能约束匿名或变化的用户名。
- 保留浏览器的 Host 和 Origin，配置明确的 `--public-origin`。代理根据实际连接来源设置限速身份，
  不能直接相信客户端提交的转发头。Robert 不从转发头推导来源身份或权限。
- 可以在代理完成认证并省略后端的 `--basic-auth-file`；此时后端的网络隔离是认证边界的一部分。
  如同时启用内置认证，代理需要转发 Authorization，每次后端请求仍会产生验证计算。

内置 `ThreadingHTTPServer` 没有认证限速或并发验证上限。HTTPS 和 `--allow-remote` 都不限制
计算负载；SSH 隧道也不替代对隧道使用者的容量控制。不能将内置 Basic 认证视为公网入口的全部防护。

## 认证计算预算

生成的 verifier 使用 600,000 次 PBKDF2-SHA256 迭代；加载器接受 600,000 至 2,000,000 次。
每个格式合法、长度允许的 Basic 请求都会执行一次完整验证，包括错误密码和错误用户名。
畸形或缺失凭据在计算前拒绝。服务端不缓存认证会话，每个静态资源及轮询请求都独立验证。

在实际部署账户和 CPU 配额下测量单次验证的 CPU 时间 `c`（秒），并将所有页面、资源、API、
轮询和失败尝试计入后端请求速率 `r`。认证平均消耗约为 `r × c` 个 CPU 核。
若分配 `b` 个核给认证，则全局转发速率必须低于 `b / c`，并为数据库、响应处理和 Worker 留余量。
页面一次需要 `n` 个请求时，仅认证就需要约 `n × c` CPU 秒；并发会增加峰值压力。

例如测得 `c = 0.15` 秒，分配 `b = 0.25` 核，则平均预算约为 1.67 个请求/秒，
10 个页面与资源请求需要约 1.5 CPU 秒。该数字仅为计算示例，不是部署性能保证。
根据页面加载需要选择有限的突发量和并发数，并验证峰值时 Worker 仍能推进；超额请求应由代理拒绝。
应使用部署中实际 verifier 的迭代次数重新测量，不能将开发机结果直接用作远程主机的容量承诺。
